# Revisions to the V5 proposal

The V5 proposal permits revising the design when a better fit exists. Each change below keeps the proposal's non-negotiable decisions (§0.1) intact.

| # | V5 text | Revision | Why |
|---|---|---|---|
| R1 | One canonical instrument string was not fixed (`BINANCE:PERP:BTCUSDT`, `hyperliquid:perp:BTC:USDC`, `BTC-USDT-PERP@BINANCE` all appear) | `{venue}:{market_type}:{venue_market_id}`, lowercase venue, e.g. `binance:perp:BTCUSDT`, `hyperliquid:perp:BTC`. Quote/settlement/version live in `InstrumentKey` | One parseable id, regex-validated in both stacks; settlement changes bump `instrument_version` without changing the id |
| R2 | Three different rule-AST examples (`op`, `all`/`any`, `ref`) | One form: Rule AST v2 with `op` discriminator (`strategy.schema.json`). BIAS takes `timeframes[]` + `match` (ALL / K_OF_N); zone binding uses `range_group` | A single typed union is easier to validate, generate and evolve; covers every example and the "K-of-N" requirement |
| R3 | `packages/drawing-tools/*/` as separate packages | One `@joseph/drawing-tools` package with one directory per tool; cross-tool imports forbidden by dependency-cruiser | Same removability (delete a directory + manifest entry) with 1 package instead of 13 |
| R4 | `packages/chart-indicators`, `indicator-viz-core` + `indicator-viz/*` | One `@joseph/indicator-viz` package mapping backend records to declarative `OverlayLayer`s | Rendering is data-driven; per-plugin modules stay separable inside the package |
| R5 | React UI inside `strategy-builder`/`chart-trading` packages | Packages are framework-free TypeScript (models, state machines, validation); React views live in `apps/web/src/features/*` | Pure logic is unit-testable without a DOM and reusable by any renderer |
| R6 | Features draw on the chart through `ChartEngineAdapter` methods | Features publish declarative overlay layers (`price-line`, `box`, `marker`) through `FeatureContext.chartLayers`; only `chart-core` talks to Lightweight Charts | Features cannot mutate chart state directly (an architecture-test requirement in §10) |
| R7 | Parquet golden fixtures | JSON/JSONL fixtures (`fixtures/indicators/...`, `packages/contracts/fixtures`) with a loader ready for Pine exports | Diffable in review; no binary dependency; Parquet can be added for bulk research data |
| R8 | PostgreSQL from day one | SQLAlchemy Core repositories; SQLite for local/dev/tests, PostgreSQL via `JOSEPH_DATABASE_URL` | Same SQL and unique constraints, zero-setup local runs; Postgres remains the production target |
| R9 | LINE notifications | LINE Messaging API push (LINE Notify was discontinued on 2025-03-31) | The proposal's channel still works with a supported API |
| R10 | Venue access via CCXT (starter) | Direct `httpx`/`websockets` adapters per venue | Exact control of timestamps, finality, sequence numbers and capability reporting; no hidden fallbacks |
| R11 | Seconds timeframes | ~~Minimum timeframe is 1m~~ Superseded by R14 | First release did not ingest trades |
| R13 | Indicators implemented inside the market engine (`plugins/<id>`) | Indicator algorithms live in `apoman123/PineScripts/python_indicators` as line-by-line Pine ports; the engine depends on it by pinned commit and keeps only SDK adapters (ADR 0009). New `market_structure` plugin for `smc_current_timeframe_structure.pine` | One source of truth per indicator ("平台歸平台，指標歸指標"); Pine changes are ported once and adopted by an explicit `rev` bump |
| R12 | Risk-blocked order submission semantics unspecified | `POST /v1/orders/intents` records and audits blocked intents and returns `201` with the `RiskDecision` and `orders: []` | The UI can show every failed check; the audit trail captures attempts |
| R14 | "Timeframes from seconds through 1M", "estimate/true delta", P2 anchored VWAP / regression channel | `1s/5s/15s/30s` are built by the engine from each venue's public trades (no perp venue publishes seconds klines), declared per venue in `trade_built_timeframes`; `1M` is a calendar month (native klines only where UTC-aligned) and all boundary math goes through `Timeframe.shift`/`end_of`. True delta comes from venue taker buy volume (`Candle.taker_buy_base_volume`) and is labelled `method: trade`; the Pine estimate stays the fallback. Anchored VWAP and the regression channel are engine series from Python-native studies in the indicator library, drawn by terminal tools | Values stay engine-computed and provenance-labelled; nothing is approximated in the browser or presented as Pine parity when it is not |
| R15 | Market scope: crypto perpetuals on five venues | Adds exchange-listed securities and rates: TWSE and TPEx stocks/ETFs (official free TWSE/TPEx sources, no key), Nasdaq/NYSE stocks/ETFs (Alpaca market data, owner's key; listings from the Nasdaq Trader directory), US Treasury par and real yield curves (`treasury:rate:*`, Treasury.gov, not tradable) and bond ETFs. New venues `twse`, `tpex`, `nasdaq`, `nyse`, `treasury`; market types `stock`/`etf`/`rate`; asset class `BOND`. Every bar boundary goes through a session calendar (`domain/sessions.py`: XTAI from TWSE's observed trading days, XNYS by NYSE rules, USBOND from Treasury's observed publication days; crypto stays `24x7`). Stock exchanges publish no aggressor side, so their delta is classified from trades against quotes (Lee-Ready / quote rule) and labelled `classified` / `trade_classification`, never `taker` | The owner asked for Taiwan and US stocks and US bonds with free data where possible; session-aligned bars match TradingView RTH charts and avoid false gaps; delta provenance stays honest |
| R16 | LIVE adapters fail closed in the first build | Real LIVE trading: Binance USDⓈ-M, Bitget (UTA), Hyperliquid, Lighter and MEXC (KYC'd keys with order permission) through signed venue APIs; securities through Interactive Brokers (IB Gateway, `ib_async`) and SinoPac Shioaji; Cathay Securities stays fail-closed until its API SDK is available; Firstrade is out of scope (no official API). The deploy configuration enables the global gate; manual LIVE orders additionally need a server-side, step-up-verified, time-limited account arming (`LIVE_NOT_ARMED` otherwise), AUTO_LIVE keeps deployment consent, and every risk-gateway check, the kill switch, idempotent client ids and the audit chain stay mandatory | The owner enabled live trading on their own accounts; arming on the server closes the gap a browser-only acknowledgement would leave |
| R17 | Seconds and true-delta history limited to each venue's trade-history window (R14) | The engine records public trades (persisted, retention configurable), imports Binance's and Bitget's official public trade archives, aggregates timeframes a venue lacks from a shorter native one that tiles them (e.g. `1M` from `1d` on Hyperliquid/Lighter) and attaches true delta to 1m+ bars only when recorded trades cover the whole bar and match its volume | History accumulates instead of being capped by venue APIs, without inventing data |
| R18 | CI reaches the private indicator library with an SSH deploy key (ADR 0009) | A fine-grained personal access token (`PINESCRIPTS_TOKEN`, Contents read-only on PineScripts only) for Actions, Dependabot and BuildKit secrets; local builds may still use SSH | Owner preference; least-privilege token scoped to one repository |
