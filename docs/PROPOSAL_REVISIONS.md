# Revisions to the V5 proposal

The proposal allows design revisions when a better fit exists. Each keeps the non-negotiable decisions (§0.1).

| # | V5 text | Revision | Why |
|---|---|---|---|
| R1 | No fixed instrument string (`BINANCE:PERP:BTCUSDT`, `hyperliquid:perp:BTC:USDC`, `BTC-USDT-PERP@BINANCE` all appear) | `{venue}:{market_type}:{venue_market_id}`, lowercase venue, e.g. `binance:perp:BTCUSDT`. Quote, settlement and version live in `InstrumentKey` | One regex-validated id in both stacks; settlement changes bump `instrument_version`, not the id |
| R2 | Three rule-AST shapes (`op`, `all`/`any`, `ref`) | Rule AST v2 with an `op` discriminator (`strategy.schema.json`); BIAS takes `timeframes[]` + `match` (ALL / K_OF_N); zones bind by `range_group` | One typed union is easier to validate, generate and evolve, and covers every example and K-of-N |
| R3 | `packages/drawing-tools/*/` as separate packages | One `@joseph/drawing-tools` package, one directory per tool; cross-tool imports forbidden | Same removability with 1 package instead of 13 |
| R4 | `chart-indicators`, `indicator-viz-core` + `indicator-viz/*` | One `@joseph/indicator-viz` mapping backend records to declarative `OverlayLayer`s | Data-driven rendering; per-plugin modules stay separable |
| R5 | React UI inside `strategy-builder` / `chart-trading` | Framework-free packages; React views in `apps/web/src/features/*` | Logic is testable without a DOM and reusable |
| R6 | Features draw through `ChartEngineAdapter` methods | Features publish declarative layers (`price-line`, `box`, `marker`) via `FeatureContext.chartLayers`; only `chart-core` touches Lightweight Charts | Features cannot mutate chart state (a §10 architecture-test requirement) |
| R7 | Parquet golden fixtures | JSON/JSONL fixtures with a loader ready for Pine exports | Diffable; no binary dependency; Parquet remains possible for bulk data |
| R8 | PostgreSQL from day one | SQLAlchemy Core; SQLite for local/dev/tests, PostgreSQL via `JOSEPH_DATABASE_URL` | Same SQL and constraints, zero-setup local runs; Postgres stays the production target |
| R9 | LINE notifications | LINE Messaging API push (LINE Notify ended 2025-03-31) | Same channel on a supported API |
| R10 | Venue access via CCXT | Direct `httpx`/`websockets` adapters | Exact control of timestamps, finality, sequences and capabilities; no hidden fallbacks |
| R11 | Seconds timeframes | ~~Minimum timeframe 1m~~ superseded by R14 | First release ingested no trades |
| R12 | Risk-blocked submission unspecified | `POST /v1/orders/intents` records and audits blocked intents and returns `201` with the `RiskDecision` and `orders: []` | The UI shows every failed check; the audit captures attempts |
| R13 | Indicators inside the market engine (`plugins/<id>`) | Algorithms live in `apoman123/PineScripts/python_indicators` as line-by-line Pine ports, pinned by commit; the engine keeps SDK adapters (ADR 0009). New `market_structure` plugin | One source of truth per indicator ("平台歸平台，指標歸指標"); Pine changes are ported once and adopted by a `rev` bump |
| R14 | Seconds through 1M, estimate/true delta, anchored VWAP and regression channel | `1s/5s/15s/30s` built from public trades (no perp venue publishes seconds klines), declared in `trade_built_timeframes`; `1M` is a calendar month, all boundary math via `Timeframe.shift`/`end_of`. True delta from taker buy volume (`method: trade`), Pine estimate as fallback. VWAP and regression are engine series from the indicator library | Values stay engine-computed and labelled; nothing is approximated in the browser or passed off as Pine parity |
| R15 | Crypto perpetuals on five venues | Adds TWSE and TPEx (official free sources), Nasdaq/NYSE (Alpaca data, owner's key; Nasdaq Trader listings), Treasury par and real yields (`treasury:rate:*`, not tradable) and bond ETFs. New venues `twse`, `tpex`, `nasdaq`, `nyse`, `treasury`; market types `stock`/`etf`/`rate`; asset class `BOND`. Every bar boundary uses a session calendar (`domain/sessions.py`: XTAI from TWSE's observed trading days, XNYS by NYSE rules, USBOND from Treasury's publication days; crypto `24x7`). Stock delta is classified (Lee-Ready / quote rule), labelled `classified`, never `taker` | The owner asked for Taiwan and US stocks and US bonds with free data where possible; session bars match TradingView RTH charts; delta provenance stays honest |
| R16 | LIVE adapters fail closed | Real LIVE on Binance, Bitget (UTA), Hyperliquid, Lighter, MEXC (KYC'd keys); securities via IBKR and SinoPac; Cathay fail-closed until its SDK; Firstrade out of scope (no official API). Deploy config enables the global gate; manual LIVE also needs server-side, step-up, time-limited account arming (`LIVE_NOT_ARMED`); AUTO_LIVE keeps deployment consent; all risk checks, kill switch, idempotency and audit stay mandatory | The owner enabled live trading on their accounts; server-side arming closes the gap of a browser-only acknowledgement |
| R17 | Seconds and true-delta history limited to venue trade history (R14) | Public trades are recorded and persisted; Binance's and Bitget's official archives are imported; missing timeframes are aggregated from shorter native ones (e.g. `1M` from `1d` on Hyperliquid/Lighter); 1m+ bars get true delta only when recorded trades cover and match them | History accumulates beyond venue API limits without invented data |
| R18 | CI reaches the indicator library with an SSH deploy key (ADR 0009) | Fine-grained token `PINESCRIPTS_TOKEN` (Contents read-only on PineScripts) for Actions, Dependabot and BuildKit; local builds may use SSH | Owner preference; least privilege on one repository |
