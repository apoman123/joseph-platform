# ADR-0006: Mandatory server-side risk gateway and OMS; fail-closed live trading

- **Status:** Accepted (2026-11-22)
- **Context:** Every order path (ticket, chart, quick trade, strategy) must be auditable and protected from duplicates, stale data and runaway automation.
- **Decision:** All orders become an immutable `OrderIntent` → deny-by-default Risk Gateway → OMS state machine → venue adapter. Only the OMS holds the execution port. Idempotency keys, a transactional outbox and reconcile-by-`client_order_id` replace any assumption of exactly-once delivery; uncertain submissions go to `UNKNOWN_RECONCILING` and are never blindly retried. LIVE requires a global flag, account capability, explicit scoped consent with step-up, and is OFF by default in code; a live adapter reports `TRADING_UNAVAILABLE` until stored credentials and a signed permission probe allow trading (see the 2026-11-23 amendment). The kill switch blocks new exposure; cancelling and flattening are separate explicit options; authorized reduce-only actions remain possible.
- **Alternatives:** Client-side risk checks (rejected: bypassable); per-adapter risk (rejected: inconsistent).
- **Consequences:** Chaos tests cover ACK loss, timeouts, duplicate/out-of-order events and cancel/fill races.
- **Migration:** Risk policy changes bump `policy_version`, recorded on every decision.
- **Rollback:** Engage the global kill switch; disable deployments; LIVE stays off.
- **Amended 2026-11-23:** venue signing and private streams are implemented for Binance, Bitget (UTA), Hyperliquid, Lighter and MEXC; an adapter reports `TRADING_UNAVAILABLE` and refuses before sending whenever the gate is off, credentials are missing or the permission probe fails. All other gates above are unchanged. Rollback: set `JOSEPH_LIVE_TRADING_ENABLED=false`.
- **Amended 2026-11-23 (account LIVE arming):** manual LIVE orders (ticket, chart, quick trade) also need a server-side, expiring account arming granted with the deployment-consent step-up check (`POST`/`DELETE /v1/accounts/{id}/live-consent`, at most `JOSEPH_LIVE_ARM_MAX_MS`, default 8 h, hard cap 24 h); without it the Risk Gateway blocks with `LIVE_NOT_ARMED` (403) except risk-reducing orders (WARN). Strategy orders keep deployment consent only, and emergency flattening, cancels and reconciliation never need arming.
