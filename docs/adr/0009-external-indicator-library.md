# ADR-0009: Built-in indicators and run-time plugin packages

- **Status:** Accepted (2026-11-22); rewritten 2026-11-24. The first version pinned a private indicator library as a git dependency of the market engine; this version replaces it. The plugin SDK of ADR 0004 stays, extended with plugin metadata.
- **Context:** A pinned private dependency meant that the public repository could not be built, tested or run without private access (forks and outside contributors could not run CI), and that the platform's contracts, rule nodes and terminal named one strategy's vocabulary. The platform needs generic indicators of its own and a way to add others without changing or naming them: "平台歸平台，指標歸指標" (the platform is a platform, indicators are indicators).
- **Decision:**
  - **Built-ins.** Nine generic indicators live in `joseph/indicators/builtin/`: `sma`, `ema`, `anchored_vwap` (shown as VWAP), `regression_channel` (drawing tools only), `bollinger_bands`, `rsi`, `atr`, `volume_delta` and `pivot_points`. They follow the published semantics of TradingView's built-in functions (`ta.sma`, `ta.ema`, `ta.rma`, `ta.stdev`, …), compute in doubles in bar order with frozen-dataclass state, publish decimals, and import no infrastructure (import-linter contract `builtin-indicators-pure`).
  - **Plugin packages.** Any installed distribution can add indicators through the entry-point group `joseph.indicator_plugins`; each entry point loads a zero-argument callable that returns its plugins in display order. Built-ins register first, then entry points sorted by entry-point and distribution name. A failing entry point or plugin is logged and skipped. A plugin is rejected when its id or one of its AOI kinds is already registered (so no package shadows a built-in), when its `schema_version` is unsupported or when its metadata is invalid.
  - **Vocabulary from metadata.** Each plugin declares its AOI kinds and event names (upper-case strings; kinds unique across plugins), its published values (type, unit, choices) and its display hints (layer, z-order, kind, event, plot and pane styles) in `IndicatorPluginInfo`. The terminal renders and the strategy compiler validates from that metadata; no platform enum, rule node or renderer names a plugin's vocabulary.
  - **Configuration.** `JOSEPH_INDICATOR_PLUGIN_PACKAGES` (`*`, `none` or entry-point names), `JOSEPH_INDICATOR_PLUGINS_DISABLED` and `JOSEPH_INDICATOR_PLUGINS_REQUIRED` (startup fails when a listed plugin is not enabled). `python -m joseph.indicators.discovery --check` lists what loads and fails on any error.
  - **Installation** happens at setup or build time, never at run time: `make plugins` locally, the image build arg `PLUGIN_REQUIREMENTS` with the optional BuildKit secret `plugin_git_token`, and in CI the variable `MARKET_PLUGIN_REQUIREMENTS` and the secret `PLUGIN_GIT_TOKEN` ([operations](../OPERATIONS.md#indicator-plugins), [CI/CD](../CI_CD.md#indicator-plugins-in-the-market-image)). A plugin package depends on the platform's SDK (`joseph-market-engine`, a compatible minor version); the platform never depends on a plugin package.
- **Alternatives:** Keep the pinned private dependency (rejected: public CI and forks cannot build, and its vocabulary leaks into public contracts); vendor third-party indicators into the repository (rejected: their licences and ownership stay with their authors); fetch plugins at run time (rejected: supply-chain risk, as in ADR 0007).
- **Consequences:**
  - The repository builds, tests and publishes without secrets; every CI job runs on fork pull requests. CI tests the built-ins only.
  - A strategy that names an absent kind, event or plugin fails validation (`KIND_UNKNOWN`, `EVENT_UNKNOWN`); a disabled plugin keeps its metadata, so its strategies report `PLUGIN_UNAVAILABLE` and never evaluate without the condition.
  - Event names may repeat across plugins: an EVENT condition may name its `source`; without one, the first registered publisher answers and the compiler warns.
  - Plugin code runs inside the market engine with its full trust, like any installed package. Operators pin requirements, allowlist entry points and require the plugins their strategies need.
  - Plugin packages keep their own licences, so engine images stay in private packages ([licensing](../reports/LICENSING_REPORT.md)).
  - `uv sync` removes locally installed plugins; `make plugins` installs them again.
  - Strategies use each plugin with its default settings (one instance per plugin id).
- **Migration:** Generic Rule AST v2 definitions keep their bytes and hashes (ADR 0005). Definitions that used the removed strategy-specific rule nodes no longer validate; a plugin package that publishes the matching vocabulary may ship its own converter. Saved workspaces that list unknown layer ids ignore them.
- **Rollback:** Redeploy a previous image tag ([rollback](../CI_CD.md#release-and-rollback)).
