# ADR-0011: Default and plugin indicators are joseph_script Indicator subclasses

- **Status:** Accepted (2026-11-28). Supersedes [ADR 0004](0004-indicator-plugin-sdk.md) and [ADR 0009](0009-external-indicator-library.md).
- **Context:** Indicators existed twice: as `IndicatorPlugin`s of a dedicated SDK (frozen-dataclass states, AOI and event metadata, a multi-timeframe engine, `/v1/indicators*` and `/v1/aois`, terminal renderers driven by `IndicatorPluginInfo`) and as Python `Indicator` scripts drawn by the terminal's script painter. Two formats meant two evaluators, two catalogs, two settings dialogs and two plugin mechanisms. Every default alert, strategy, indicator and filter is now a class that inherits its abstract base in `joseph_script`; anything else is legacy (see [ADR 0010](0010-python-strategy-scripts.md) for strategies).
- **Decision:**
  - **One format.** An indicator is a concrete `joseph_script.Indicator` subclass: built-in, an installed plugin or an immutable tenant script version. The plugin SDK, its built-ins, discovery, engine, query service and golden/testing helpers (`joseph.indicators`) are deleted.
  - **Built-ins.** `joseph.scripts.builtin.indicators` holds the nine generic indicators, served as `builtin:sma`, `builtin:ema`, `builtin:anchored_vwap`, `builtin:regression_channel`, `builtin:bollinger_bands`, `builtin:rsi`, `builtin:atr`, `builtin:volume_delta` and `builtin:pivot_points`. They follow TradingView's published built-in semantics, keep incremental O(n) state on the instance, declare their settings (including style colors) as `INPUTS` and their extra series as `REQUESTS`, import only `joseph_script` and the standard library (import-linter contract `builtin-scripts-pure`) and are valid tenant source.
  - **Plugins.** Distributions publish `Indicator` classes through the entry-point group `joseph.scripts` (catalog id `plugin:<entry point>:<ID>`), configured with `JOSEPH_SCRIPT_PLUGIN_PACKAGES`, `JOSEPH_SCRIPT_PLUGINS_DISABLED` and `JOSEPH_SCRIPT_PLUGINS_REQUIRED`; `python -m joseph.scripts.catalog --check` lists what loads. Installation stays a setup or build step ([operations](../OPERATIONS.md#script-plugins)); the platform never depends on or names a plugin package.
  - **Routes.** `GET /v1/scripts/catalog[?kind=indicator]` lists the catalog with declared inputs and requests, `GET /v1/scripts/catalog/{id}` adds a built-in's public source, `POST /v1/scripts/{id}/run` runs one study and `POST /v1/scripts/run-batch` runs up to sixteen studies over one fetch of the chart candles. Catalog classes run in process with an exact-input result cache; their history reads yield the venue rate limit to chart requests.
  - **Context extensions.** Intrabar requests (`Request(..., intrabars=True)` with `tf="auto"`, `tf_input`, `unless` and `unless_input`; fetched only for the newest bars that need them, from the run's `window_from_ms`) read through `ctx.intrabars(alias)`; `ctx.closed_bar(alias)` reads the latest closed bar of a declared series; `PERIODS` with `ctx.period(tf)` give calendar periods on the instrument's session calendar; `ctx.plot(..., display="data_window")` lists values without drawing them; runs read up to 5,000 bars ([Python scripts](../PYTHON_SCRIPTS_AND_MCP.md#context-extensions-for-indicators)).
  - **Pivot points** draw each period's levels as labelled lines and raise a touch alert on the first confirmed bar inside the period that reaches a level, instead of publishing AOIs. Volume delta draws true delta from venue taker (or classified) buy volume and otherwise an intrabar estimate with its coverage, labelled in the pane.
  - **Terminal.** Charts keep `ChartState.studies` (script id, pinned version for owned scripts, inputs, plot colors, visibility); workspace schema v2 migrates the v1 indicator layers and attached scripts. All studies run and render through the same script path, legend, settings dialog (generated from `INPUTS`) and picker (Built-ins, Plugins, My scripts). Anchored VWAP and regression channel drawings run their built-in scripts.
  - **DEMO.** A small TypeScript evaluator produces `ScriptResult`-shaped DEMO data for the nine built-in ids. It is DEMO data generation, not an alternative implementation: a parity test compares it with outputs exported from the Python built-ins on fixed bars (`contracts/fixtures/builtin-indicator-outputs.json`, written by `scripts/export_openapi.py`).
- **Alternatives:** Keep the SDK beside scripts (rejected: duplicated semantics, contracts and renderers); keep AOIs as a published output of scripts (rejected: a second visual model next to drawings; scripts that need levels draw them and raise alerts).
- **Consequences:** `/v1/indicators/plugins`, `/v1/indicators/snapshot`, `/v1/indicators/series`, `/v1/aois`, the `aois` stream channel and the `IndicatorPluginInfo`, `IndicatorSeries`, `IndicatorSnapshot` and AOI contracts are removed. The hand-derived golden scenarios stay in `fixtures/indicators/` and are reproduced by `tests/replay/scripts/test_builtin_indicator_golden.py`. Values are doubles: the tick-based decimal rounding of published values is gone, and fixtures compare at their former precision. An anchored study reads at most 5,000 bars per run; a farther anchor is reported instead of drawn. Pivot levels have no separate confirmation time.
- **Migration:** External packages publish their indicators as `Indicator` classes under `joseph.scripts`; their ids change to `plugin:<entry point>:<ID>`. Saved workspaces migrate automatically (built-in layers that were shown become studies; layers of former plugin packages are dropped). `JOSEPH_INDICATOR_PLUGIN_PACKAGES`, `JOSEPH_INDICATOR_PLUGINS_DISABLED` and `JOSEPH_INDICATOR_PLUGINS_REQUIRED` are replaced by the `JOSEPH_SCRIPT_PLUGIN_*` settings.
- **Rollback:** Revert the change set; schema v2 workspaces would need the v1 layers re-added by hand.
