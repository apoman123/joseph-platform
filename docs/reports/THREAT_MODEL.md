# Threat model (STRIDE, compact)

The main threats to Joseph, their mitigations and the tests that verify them, grouped by STRIDE plus trading-specific risks. For operators and security reviewers.

- **Assets:** venue and broker credentials, the ability to place orders, strategy IP, tenant data, audit integrity.
- **Public source:** no control relies on secrecy of code. Credentials, keys and deployment settings live outside the repository (vault, `deploy/.env`, GitHub Secrets), and optional indicator plugin packages ship only in private images.
- **Trust zones:** browser (untrusted) → market engine (server side; data keys only, no trading credentials) → execution engine (server side; encrypted credentials) → venues and brokers.

| Threat | Example | Mitigation | Verified by |
|---|---|---|---|
| Spoofing | Forged request or WebSocket message places an order | Bearer auth on every execution endpoint; service token on `/internal/v1/signals`; user WS needs a token; LIVE needs the global flag plus step-up: scoped deployment consent (strategies) or expiring server-side account arming (manual, else `LIVE_NOT_ARMED`) | Execution security tests (auth on all routes; forged WS/HTTP cannot reach a live adapter); `integration/test_live_arming.py` |
| Tampering | Edited preview parameters at submit; altered audit rows | HMAC preview token bound to normalized parameters and expiry; hash-chained append-only audit (`chain_valid`) | Preview tamper/expiry tests; audit tamper test |
| Repudiation | "I never sent that order" | Every intent, decision, submit/cancel/amend, kill switch, consent, arming (granted, denied, revoked) and credential change is audited with actor and trace id | Audit integration tests |
| Information disclosure | API secret in logs, responses or the JS bundle | AES-GCM envelope encryption; redaction log filter; secrets never serialized; browser holds only a session token; CI secret scan | Vault/redaction tests; `pnpm secrets:scan`; dependency-cruiser bans server code in the browser |
| Denial of service | Venue rate limits, WS floods | Per-venue throttling at documented weights (refused before sending when exhausted), jittered reconnect, bounded queues; 429/418 → `RATE_LIMITED` and the venue pauses | Adapter 429/timeout tests, `unit/venues/test_venue_infra.py` |
| Key misuse | Withdrawal-capable or master keys used for trading | Withdrawal-capable keys refused by attestation; Binance verifies `enableWithdrawals=false`; Hyperliquid refuses the master key as agent; Lighter refuses reserved key indexes; broker logins never pass through the API; secrets redacted in reprs, errors and logs | `unit/venues/`, `integration/test_live_venues.py` |
| Elevation of privilege | Tenant A reads or cancels tenant B's orders; a feature flag enables LIVE | Tenant scoping in every query (foreign ids → 404); flags cannot grant trading; deny-by-default risk gateway | Tenant-isolation tests (REST + WS); mode-gate tests |
| Duplicate or runaway orders | Lost ACK, partition, replayed signal | Idempotency keys, transactional outbox, `UNKNOWN_RECONCILING` + reconcile by `client_order_id`, once-per-signal intake, kill switch | Chaos and property tests |
| Supply chain and CI | A tampered third-party action, a malicious fork pull request, a leaked engine image, a hostile indicator plugin package | Third-party actions pinned to commit SHAs (Dependabot updates them); fork workflows need maintainer approval and get no secrets; deploys need environment approval and run only from `main` and `v*` tags; engine images publish only into private packages. Plugins install only at setup or build time from operator-pinned requirements, never at run time; `JOSEPH_INDICATOR_PLUGIN_PACKAGES` allowlists entry points; the market engine holds no trading credentials | `security.yml` on `main`, pull requests and weekly (CodeQL incl. Actions, gitleaks, audits, dependency review); `.github/actions/private-image`; discovery tests (failure isolation, duplicate ids and kinds) |
| Bad data → bad trades | Stale book, unclosed HTF bar, DEMO data, unknown holdings | Provenance on every value; stale or unknown → BLOCK; confirmed-bar evaluation; DEMO/REPLAY never tradable live; position mismatch blocks new exposure | No-look-ahead properties; risk data-quality tests |

**Residual risks:** no production identity (OIDC + MFA) or BFF (dev tokens only); the KMS is a local master key; venue keys are decrypted in process per signed request (no HSM or remote signer); MEXC has no sandbox, so its adapter is verified only against documented payloads; indicator plugin packages run in the market engine's process without a sandbox; no WAF or edge rate limiting.
